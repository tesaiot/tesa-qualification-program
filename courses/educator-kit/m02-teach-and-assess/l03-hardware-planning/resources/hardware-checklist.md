# รายการตรวจความพร้อมฮาร์ดแวร์สำหรับรายวิชา

ใช้คู่กับบทเรียน "วางแผนฮาร์ดแวร์" ของชุดสำหรับผู้สอน ตรวจก่อนเปิดภาคการศึกษา และก่อนแล็บแรกอีกครั้ง

## จำนวน

- [ ] บอร์ด: จำนวนผู้เรียน ÷ 3 หรือ 4 ปัดขึ้น บวกสำรองอย่างน้อยหนึ่งถึงสองชุด
- [ ] สาย USB ที่ส่งข้อมูลได้ (ไม่ใช่สายชาร์จอย่างเดียว) เท่าจำนวนบอร์ด บวกสำรอง
- [ ] เครื่องคอมพิวเตอร์ที่ต่อบอร์ดได้ อย่างน้อยหนึ่งเครื่องต่อหนึ่งบอร์ด

## ซอฟต์แวร์และเครือข่าย

- [ ] เบราว์เซอร์ Chrome หรือ Edge บนคอมพิวเตอร์ (BENTO IDE ต่อบอร์ดผ่าน WebSerial)
- [ ] ทดลองเปิด https://ide.tesaiot.dev/ และ BENTO Emulator จากเครือข่ายของสถาบัน
- [ ] เฟิร์มแวร์บนบอร์ดทุกตัวเป็นรุ่นเดียวกัน และจดเลขรุ่นไว้
- [ ] WiFi สำหรับบทเรียนที่ใช้เครือข่าย: เครือข่ายที่ต้องล็อกอินผ่านหน้าเว็บมักใช้กับบอร์ดไม่ได้ เตรียม Hotspot หรือเครือข่ายสำหรับแล็บ
- [ ] ทดสอบว่าเครือข่ายของสถาบันไม่กันพอร์ตที่บทเรียน MQTT ใช้ (เช่น 1883 สำหรับ broker สาธารณะในบทเรียนระดับต้น)
- [ ] ไม่มีรหัส WiFi จริงอยู่ในไฟล์ที่แจกผู้เรียนหรือขึ้นที่สาธารณะ

## การจัดการ

- [ ] ติดหมายเลขบอร์ดทุกตัว และมีทะเบียนยืม–คืน
- [ ] กล่องเก็บที่กันไฟฟ้าสถิต และกติกาการจับบอร์ด (จับขอบ ไม่วางบนโลหะ)
- [ ] แผนเมื่อบอร์ดเสียระหว่างแล็บ (สำรอง หรือย้ายไปทำส่วนที่ทำในอีมูเลเตอร์ได้)
- [ ] ถ้าใช้ remote flash: ทดลองจับคู่เครื่องที่ต่อบอร์ดกับหน้า https://flash.tesaiot.dev/ ก่อนวันแล็บ

## ก่อนแล็บแรก

- [ ] ผู้สอนรันตัวอย่างของแล็บนั้นบนบอร์ดจริงอย่างน้อยหนึ่งตัวแล้ว ไม่ใช่แค่ในอีมูเลเตอร์
- [ ] จดความต่างระหว่างผลบนบอร์ดกับในอีมูเลเตอร์ที่พบ แล้วบอกผู้เรียนล่วงหน้า
