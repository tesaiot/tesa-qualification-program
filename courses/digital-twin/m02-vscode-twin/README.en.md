
# Module 2 — VS Code for Twin Development

*VS Code for Twin Development* · [Firmware Development with the VS Code-based TESA Digital Twin](../README.md) course

## Objectives

Install Bitstream Studio, bind the workspace to the firmware or the lab pack, then open a first reproducible session, whether Simulator and/or Bitstream (UART).

## Lessons

| # | Lesson | Content |
|---|---|---|
| 1 | [Setting up the Twin host in VS Code with Bitstream Studio](l01-vscode-for-twin/README.md) | Installing Bitstream Studio (Marketplace or VSIX), arranging the workspace, binding the firmware, knowing the backend services, and troubleshooting a blank UI |
| 2 | [Lab: installing the Twin in VS Code and a first session](l02-lab/README.md) | Installing Bitstream Studio, binding the workspace, opening a first session (Simulator or Bitstream), then observing and switching paths |

Approximate time per the original: about 3 hours (lessons) + a 2–3 hour lab (including installation).

Accompanying sheets and templates (in the `resources/` folder of lesson 1):

- [vscode-twin-setup.md](l01-vscode-for-twin/resources/vscode-twin-setup.md)

## Checkpoint

Before moving to the next module, check that you can do the following:

- [ ] Bitstream Studio is ready to use, and the backend is up
- [ ] The workspace can point at the firmware project or the lab pack
- [ ] A first session succeeds on at least one path, with a screenshot
- [ ] vscode-twin-setup.md filled in completely
