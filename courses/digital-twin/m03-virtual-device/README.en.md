
# Module 3 — Virtual Device Modeling (+ Blender for Twin 3D)

*Virtual Device Modeling (+ Blender for Twin 3D)* · [Firmware Development with the VS Code-based TESA Digital Twin](../README.md) course

## Objectives

Design what the Twin simulates: a device model with sensors, behaviour, and a repeatable event script, together with Blender basics for the 3D model the Twin displays.

## Lessons

| # | Lesson | Content |
|---|---|---|
| 1 | [Virtual Device, behavior, event scripts and a 3D model for the Twin](l01-virtual-device-modeling/README.md) | Defining the device model, sensors, behaviour, and a timed event script, then preparing a 3D model in Blender to export as GLB for the Twin |
| 2 | [Lab: building a Virtual Device and an event script](l02-lab/README.md) | Building the device model, defining behaviour, writing a repeatable event script, and (recommended) a brief Blender exercise, exporting a GLB |

Approximate time per the original: about 4–5 hours (lessons) + a 3–3.5 hour lab (+ 1–1.5 hours if doing Lab E Blender).

Accompanying sheets and templates (in the `resources/` folder of lesson 1):

- [blender-twin-cheatsheet.md](l01-virtual-device-modeling/resources/blender-twin-cheatsheet.md)
- [device-model-checklist.md](l01-virtual-device-modeling/resources/device-model-checklist.md)
- [sample-virtual-device.template.json](l01-virtual-device-modeling/resources/sample-virtual-device.template.json)

## Checkpoint

Before moving to the next module, check that you can do the following:

- [ ] A device-model.json (or equivalent) with ≥ 2 sensor types
- [ ] At least one behaviour path with an observable result
- [ ] A repeatable event script, with evidence of the result in the visualization
- [ ] (Recommended) a `.glb` file from Blender
