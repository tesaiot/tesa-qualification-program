
# Module 6 — System Integration and Testing

*System Integration and Testing* · [Firmware Development with the VS Code-based TESA Digital Twin](../README.md) course

## Objectives

Combine Modules 1–5 into a repeatably demonstrable system: stimulus → firmware → Studio → dashboard/MQTT, with an E2E test table of at least three cases, and a README that can be rerun.

## Lessons

| # | Lesson | Content |
|---|---|---|
| 1 | [End-to-end testing on the Digital Twin](l01-system-integration-testing/README.md) | The Capstone's minimum pass criteria, analysing logs layer by layer, a task from a real domain, and the Smart Environmental Monitor case study |
| 2 | [Capstone lab: an E2E mini-project on the Digital Twin](l02-lab/README.md) | Locking the architecture, assembling a working demo, running three E2E test cases, practising log tracing, and packaging a handover |

Approximate time per the original: about 2 hours (lessons) + a ~2 hour lab + extra time for the README and evidence.

Accompanying sheets and templates (in the `resources/` folder of lesson 1):

- [course-package.md](l01-system-integration-testing/resources/course-package.md)
- [e2e-case-brief.md](l01-system-integration-testing/resources/e2e-case-brief.md)

## Checkpoint

Before moving to the next module, check that you can do the following:

- [ ] A repeatable demo covering the full path: stimulus → firmware → Studio → consumer
- [ ] An E2E test table with ≥ 3 cases and real results
- [ ] A README covering bring-up → demo → teardown
- [ ] No secrets in the handed-over files
