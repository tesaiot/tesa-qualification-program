# Decision Canvas สำหรับโครงการ Edge AI และ IoT (หนึ่งหน้า)

แม่แบบนี้เป็นผลงานท้ายหลักสูตร "Edge AI และ IoT สำหรับการตัดสินใจเชิงผลิตภัณฑ์" คัดลอกไปเติมได้เลย
เติมให้สั้นที่สุดที่ยังชัด ช่องไหนยังไม่รู้ ให้เขียนว่า "ยังไม่รู้ ต้องถาม ..." ดีกว่าเดา

| # | หัวข้อ | สิ่งที่ต้องเขียน | ของคุณ |
|---|---|---|---|
| 1 | ปัญหาและผู้ได้รับผลกระทบ | ปัญหาคืออะไร เกิดกับใคร เกิดบ่อยแค่ไหน เสียหายอย่างไร | |
| 2 | โจทย์สามส่วน | วัดอะไร · ตัดสินใจอะไร · ใครทำอะไรต่อ (ประโยคเดียว) | |
| 3 | บันไดก่อน AI | หยุดที่ขั้นไหน: วัดได้ไหม / กฎพอไหม / ต้องจำรูปแบบ | |
| 4 | ตัวชี้วัดความสำเร็จ | วัดอย่างไรว่าได้ผล เช่น เตือนผิดไม่เกินกี่ครั้งต่อเดือน พลาดไม่เกินเท่าไร | |
| 5 | สถาปัตยกรรม | edge / cloud / hybrid และมิติที่ใช้ตัดสิน (ความหน่วง ความเป็นส่วนตัว ต้นทุน การเชื่อมต่อ) | |
| 6 | หน้างาน | ติดตั้งที่ไหน ไฟเลี้ยงจากอะไร สัญญาณเครือข่ายเป็นอย่างไร สภาพแวดล้อม (ร้อน ชื้น ฝุ่น) | |
| 7 | ข้อมูล | ข้อมูลอะไรที่มีอยู่แล้ว ต้องเก็บเพิ่มอะไร ใครติดป้ายกำกับ (ถ้าใช้ AI) | |
| 8 | ต้นทุนสามก้อน | ครั้งเดียว (NRE) · ต่อชิ้น (BOM) · ต่อเนื่อง ตัวเลขที่รู้แล้ว และตัวเลขที่ยังต้องขอใบเสนอราคา | |
| 9 | เวลา | เป้าหมายของแต่ละช่วง: พิสูจน์แนวคิด · ต้นแบบ · นำร่อง · ผลิต | |
| 10 | ความเสี่ยงสามอันดับแรก | จากทะเบียนความเสี่ยง พร้อมวิธีลดและผู้รับผิดชอบ | |
| 11 | กฎและมาตรฐานที่ต้องตรวจ | PDPA (ข้อมูลส่วนบุคคลหรืออ่อนไหว) · กสทช. (วิทยุ) · สมอ. (มอก.) · อย. (ถ้าอ้างสรรพคุณทางการแพทย์) | |
| 12 | ทำเอง ซื้อ หรือพันธมิตร | ทางเลือกที่เลือก พร้อมเหตุผลหนึ่งประโยค | |
| 13 | สิ่งที่ต้องได้คืนเมื่อจบงาน | ซอร์สโค้ด ไฟล์ออกแบบ เอกสาร กุญแจ ข้อมูล | |
| 14 | ขอบเขตรอบแรก | สิ่งที่ทำในรอบนี้ และสิ่งที่ **ไม่ทำ** ในรอบนี้ | |
| 15 | ผู้ตัดสินใจและผู้ติดต่อ | ใครอนุมัติ ใครตอบคำถามหน้างาน | |
